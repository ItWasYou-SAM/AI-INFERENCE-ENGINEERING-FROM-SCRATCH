Attention lets each token pull in information from the tokens before it. For each token, three vectors are projected from the
residual stream ([1.2](/learn/m01/inside-a-transformer-layer)):

- a **query** $q$: what this token is looking for,
- a **key** $k$: what this token offers to others,
- a **value** $v$: what it actually hands over when picked.

$$
Q = hW_Q \qquad K = hW_K \qquad V = hW_V \qquad\qquad Q, K, V \in \mathbb{R}^{T \times d_h}
$$

## Four steps

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_h}} + M\right) V
$$

1. **Scores.** $S = QK^\top / \sqrt{d_h}$ is a $T \times T$ matrix. Entry $(i, j)$ says how relevant key $j$ is to query $i$.
   Dividing by $\sqrt{d_h}$ keeps the scores from growing with the head size, which would make softmax too peaked.
2. **Mask.** $M$ is $0$ on and below the diagonal and $-\infty$ above it. A token cannot look at tokens that come after it.
3. **Softmax.** Each row becomes a set of weights that sum to 1. The $-\infty$ entries become exactly 0.
4. **Weighted sum.** Row $i$ of the output is $\sum_j A_{ij}\, v_j$: a blend of the values, weighted by relevance.

## Why the mask matters for inference

The causal mask exists for training: the model learns to predict token $t+1$ from tokens $0 \dots t$, so it must not see $t+1$. It has a
consequence that inference relies on heavily:

<Callout type="insight">
  Row $i$ of the attention output depends only on $q_i$ and on $k_0 \dots k_i$, $v_0 \dots v_i$. Adding a new token at the end **does not
  change** any earlier row, or any earlier $k$ or $v$. So the keys and values of past tokens can be computed once and reused for every later
  step. That reuse is the [KV cache](/learn/m01/why-kv-cache).
</Callout>

## Multi-head attention

Real models run $n_h$ attention **heads** in parallel, each with its own slice of $W_Q, W_K, W_V$ of width $d_h = d / n_h$
(typically 64 or 128). Each head can learn a different pattern: one tracks the previous token, another tracks the subject of the sentence.
The head outputs are concatenated back to width $d$ and mixed by $W_O$.

Implementation-wise, heads are just an extra batch dimension: reshape $[T, d]$ into $[n_h, T, d_h]$, run attention on every head at
once, and reshape back. Grouped-query attention (GQA) lets several query heads share one K/V head, which shrinks the cache;
chapter [9.2](/learn/m09/mqa-gqa-mla) covers it.

## What attention costs

| | Prefill ($T$ prompt tokens) | Decode (1 new token, context $n$) |
|:--|:--|:--|
| Score matrix | $T \times T$ | $1 \times n$ |
| FLOPs per layer | $\approx 4T^2 d$ | $\approx 4nd$ |
| Bytes read | $Q$, $K$, $V$ for $T$ tokens | the **whole** cached $K$ and $V$ for $n$ tokens |

In prefill, attention is quadratic in prompt length, and it is a lot of math on data already loaded: compute-heavy. In decode, a single query
row has to read every cached key and value to do very little math with each. That makes decode attention memory-bound, and unlike the
weight matmuls, batching more requests does not help it ([3.3](/learn/m03/roofline)).

## Lab: attention with every intermediate printed 🟢

```python title="labs/m01/1.3/attention.py"
S = Q @ K.T / np.sqrt(dh)                            # [T, T]
mask = np.triu(np.ones((T, T), dtype=bool), k=1)     # True above the diagonal = the future
S_masked = np.where(mask, -np.inf, S)
A = softmax(S_masked)                                # rows sum to 1
out = A @ V
```
